## AI Diary (Required - 100+ words)
ตอนเริ่มผมอ่านโค้ดเดิมก่อนวางแผน และพบว่าหน้า Analysis มีตัวเลือกน้ำยาอยู่แล้ว จึงเลือกต่อยอดเป็นแท็บแทนการสร้างหน้าใหม่ ผมเกือบถามผู้ใช้เรื่องขนาดสติกเกอร์ผิดแนวทาง คือเสนอ 25x15 มม. เป็นค่าแนะนำ แต่ผู้ใช้ใช้ 50x35 มม. จริง ซึ่งสอนให้รู้ว่าค่าที่ "แนะนำ" ควรอิงกับของที่ผู้ใช้มีอยู่จริง ผมประหลาดใจที่กฎในโปรเจกต์บอกว่า "ยังไม่มี test framework" ทั้งที่มี vitest และ PGlite อยู่แล้ว จึงตรวจจากโค้ดจริงแทนที่จะเชื่อเอกสาร จุดที่ระวังที่สุดคือ parser บาร์โค้ด เพราะเป็นเส้นทางเสี่ยง production ผมจึงให้ QR ของเราจับคู่ได้เฉพาะ itemId ตรงตัว และเขียนเทส regression ให้ GS1 กับ pattern เดิม ส่วนที่ยังไม่แน่ใจคือผลการปริ้นจริงบนเครื่องความร้อน ซึ่งผมตรวจจากเครื่องนี้ไม่ได้ ท้ายสุดคำขอ "ทดสอบ API ต่าง ๆ" กำกวมและเสี่ยงถ้าชี้ไปฐานข้อมูลจริง ผมจึงเลือกถามก่อนแทนที่จะยิงเอง

## Lessons Learned
- **Pattern**: ตรวจโค้ดจริงก่อนเชื่อเอกสารสรุป (เอกสารบอกไม่มีเทส แต่มี vitest + PGlite)
- **Pattern**: ฟีเจอร์ที่แตะ parser/สต็อก ให้แยก PR เล็ก, ทำให้จับคู่แบบตรงตัวเท่านั้น และมีเทส regression ของรูปแบบเดิม
- **Pattern**: ถามขนาด/อุปกรณ์จริงของผู้ใช้ก่อนใส่ค่าเริ่มต้นในแผน
- **Pattern**: ก่อนยิง API กับระบบ production ให้ยืนยันก่อนว่า `.env.local` ชี้ฐานข้อมูลไหน
