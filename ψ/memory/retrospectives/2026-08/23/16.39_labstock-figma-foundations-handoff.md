## AI Diary

I began with a strong assumption that the requested Figma page hierarchy could be created literally. The first write exposed an important constraint: the authenticated Starter plan allows only three pages. I stopped, read the recovery guidance, verified that the failed operation was atomic, and redesigned the file architecture around three pages with workflow sections. That compromise preserves the intended taxonomy without pretending the account supports unlimited pages. The token work was more successful: the existing application already had a coherent clinical teal palette, so translating it into primitive and semantic aliases produced a useful handoff instead of an ornamental mood board. The biggest surprise was reaching the Starter MCP call limit exactly when beginning the Button component set. I resisted moving into source-code implementation because the user explicitly required Figma approval first. The local browser check also showed why evidence needs to stay separated: a healthy login page and clean console do not prove authenticated workflows. The cleanest continuation is to resume from P1.d after quota recovery, complete responsive Auth and App Shell frames, obtain approval, and only then integrate the tokens into code.

## Lessons Learned

- **Starter architecture**: ใช้ 3 Figma pages และแบ่ง workflow ด้วย Section nodes เมื่อ page quota จำกัด
- **Atomic recovery**: เมื่อ `use_figma` ล้มเหลว ต้อง inspect ก่อน retry; คำสั่งที่ชน page/tool limit ไม่ทิ้ง partial nodes
- **Token-first handoff**: การ alias semantic colors จากค่าจริงใน `globals.css` ทำให้ Figma และ code พร้อมเชื่อมกันภายหลัง
- **Evidence separation**: HTTP 200 และหน้า Login ไม่มี console error ยังไม่ใช่ authenticated workflow acceptance
- **Approval discipline**: ไม่เริ่มย้าย design เข้า source code ก่อน Phase 1 Figma ได้รับการตรวจรับ
