## AI Diary (Required - 100+ words)

This session began with two related but distinct operational gaps: users could register with an email address but an administrator had no safe way to release the account, and PO information could be viewed but not exported as a usable supplier document. I first treated account activation as an authorization change rather than a display change. That exposed the risk of activating a Vendor who had only requested a new company, so the endpoint now requires an approved company association and protects the last active administrator. For exports, the available project libraries supported browser printing but not native XLSX or PDF writing. I chose the existing browser-safe pattern: a UTF-8 CSV that opens in Excel and an A4 print view for Save as PDF. An independent review found that the first export draft could leak an internal Lab note to Vendor and could allow spreadsheet formula injection. Both issues were corrected before release. The deployment is Ready, but that means Vercel built the code; it does not prove an authenticated Lab or Vendor has completed the workflow in Production.

## Lessons Learned

- **Pattern**: Account status transitions must enforce company ownership and administrator safety at the API boundary, not just by hiding UI controls.
- **Pattern**: Export DTOs must be audience-specific; a raw PO row can contain internal workflow fields that a Vendor must not receive.
- **Pattern**: A READY deployment and public HTTP response are release evidence, not authenticated end-to-end acceptance evidence.
