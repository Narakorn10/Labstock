## AI Diary (Required - 100+ words)

I began with a narrow symptom: empty stock that did not become a suggested order. The live calculation made the diagnosis unusually concrete: old confirmed orders with passed expected dates were effectively transformed into inventory by the projection loop. I initially treated the issue as a suggestion threshold problem, but the live data disproved that because the dynamic quantity was zero only after overdue arrivals were counted. The loan feature then revealed a related data-model limitation: the existing borrow and lend screens altered stock but discarded the partner and return obligation, so historical debt could not be reconstructed safely. I chose a forward-only ledger instead of guessing from generic receive and dispense logs. The deployment also exposed a Vercel link mismatch: the local link used the retired project name while the active production project was `stocklabspr`. Re-linking to the existing project preserved aliases and allowed the authorized deployment.

## Lessons Learned

- **Projection integrity**: An expected delivery date is not proof of available inventory once that date has passed; overdue arrivals must be review signals, not virtual stock.
- **Loan traceability**: A stock movement alone is insufficient for borrowing workflows; partner, lot, direction, remaining balance, and the closing return must be persisted together.
- **Deployment identity**: Confirm the Vercel project name and owner separately from a local `.vercel` link before deploying.
