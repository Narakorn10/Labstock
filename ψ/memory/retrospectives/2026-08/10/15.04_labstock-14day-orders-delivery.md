## AI Diary (Required - 100+ words)

I began by treating the existing uncommitted formula as work to validate rather than as an assumption to preserve. The key surprise was that the draft implementation used recent consumption not only to decide when stock was at risk, but also to increase the quantity above the laboratory's reviewed policy. Local RAG surfaced the older operational rule that current stock and demand should determine the trigger while the approved worksheet quantity should determine how much to buy. I therefore kept the useful part of the draft—actual dispense history—but narrowed it to a true 14-day calendar window and restored the approved quantity as authoritative. I also noticed that the dashboard API already exposed current quantity and minimum threshold, which made the UI change small and schema-free. ## Lessons Learned

- **Pattern**: Separate reorder timing from approved purchase quantity; demand projections may raise a recommendation but should not silently replace reviewed laboratory policy.
- **Pattern**: A “14-day” model must query a bounded 14-day window, not divide all-time usage by the full history age.
- **Pattern**: Reuse current inventory data already returned by `/api/dashboard` instead of adding duplicate queries or schema changes.
- **Pattern**: Build and HTTP success do not replace an authenticated visual workflow check; keep that gate explicit when no browser session is available.
- **Pattern**: Verify the active GitHub identity against the repository owner before push, especially when multiple keyring accounts are configured.
