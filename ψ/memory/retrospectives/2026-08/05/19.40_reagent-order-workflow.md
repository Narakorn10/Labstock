## AI Diary (Required - 100+ words)

The session began with a plan that correctly identified the existing purchase-order, shipment, and inventory paths, but the first implementation delegation did not return patches within the bounded window. I took the critical path back after preserving the untracked v13 migration. The most important surprise was that the old workflow looked complete at the UI level while its status contract diverged in several places: partial shipment states were emitted by APIs but omitted from screens, and Vendor confirmation could bypass acknowledgement. The outsider review also exposed that LINE postbacks were trusted after signature validation without checking the linked actor or current PO state. I corrected those issues and then extended receiving to distinguish accepted and rejected quantities. I deliberately did not run the database migration, commit, push, or deploy because those actions need a separate controlled validation step. The remaining risk is transactional consistency between shipment receipt and PO counters, which needs a real database smoke test before production use.

## Lessons Learned

- **Pattern**: Existing workflow state must be centralized or every Web, LINE, and LIFF path can silently diverge.
- **Pattern**: Passing lint/build does not validate SQL schema compatibility or atomic inventory/PO behavior.
- **Pattern**: A valid LINE signature authenticates the channel, not the business actor; linked-user role and current-state checks are still required.
