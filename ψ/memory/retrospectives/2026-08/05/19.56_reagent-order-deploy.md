## AI Diary

I resumed from a working tree that already contained a broad reagent-order implementation and a WIP note naming migration, atomicity, and LIFF contract checks as unfinished. The important discovery was that the shipment endpoint claimed the shipment and updated inventory in one SQL statement, but updated purchase-order counters afterward through separate requests. That left a real consistency gap: a later failure could make inventory say an item was received while the PO remained open. I corrected this with Neon’s non-interactive transaction API and made rejected quantity count toward fulfillment while only accepted quantity enters inventory. I also aligned the LIFF review path with the action vocabulary and ensured revision quantities are applied or cleared atomically. Before migration, I queried the live configured Neon schema without changing data; v13 and v14 were already present, while the v10/v15 workflow fields were absent. I applied only the additive workflow migrations, deliberately skipped the manual business-plan data migration, verified the columns, committed and pushed the intended 13 files, and deployed production. The deployment build and a protected production curl succeeded. The remaining uncertainty is behavioral smoke coverage against authenticated API paths and real user roles, which was not run because the available checks did not provide safe synthetic actors.

## Lessons Learned

- **Pattern**: A CTE is only atomic for the statements inside it; follow-up HTTP SQL calls still need an enclosing transaction.
- **Pattern**: Schema presence should be checked before applying additive migrations, especially when migration files are split across prior sessions.
- **Pattern**: A READY Vercel deployment and root-page response do not prove authenticated business workflows.
