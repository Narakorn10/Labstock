## AI Diary (Required - 100+ words)

I treated the requested workflow as an inventory-safety change rather than a screen-only change. The critical design decision was to keep counting separate from deduction, so saving a work order cannot reduce main stock and confirmation can make all inventory changes together. I was careful to preserve the dirty working tree because it contains parallel user work that is not part of this feature. The local Auth.js error was initially surfaced as a generic server configuration failure, but a direct session-endpoint check narrowed it to the absent development secret. I restarted the local process with an ephemeral environment value rather than writing a secret into project files. This made local page checks possible while avoiding a hidden configuration change. I also found a pre-existing TypeScript failure in `src/auth.ts`, so type-check/build cannot yet be claimed clean. The current desktop implementation calculates FEFO allocations, but its UI still needs direct lot change/split controls to fully match the original plan.

## Lessons Learned

- **Inventory safety**: Persisting count intent first and locking current lot quantities only at confirmation keeps provisional work from changing stock.
- **Local auth**: A generic Auth.js configuration page can be isolated quickly by checking `/api/auth/session`; local dev secrets should stay out of tracked files.
- **Release gate**: Passing unit tests and unauthenticated HTTP checks does not replace authenticated role tests or approval to apply a schema migration.
