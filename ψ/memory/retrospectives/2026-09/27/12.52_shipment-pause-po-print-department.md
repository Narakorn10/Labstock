## Lessons Learned
- **Pattern**: When a user's global CLAUDE.md marks a specific named project as "production, ask before risky changes," the harness's own auto-mode classifier will independently block irreversible/production-adjacent actions (destructive file rewrites via script, running migrations, polling deploy status) regardless of what the user's instructions say. Don't try to route around a classifier denial with a different tool — the correct response is to do everything else, then hand the single blocked step back to the user with the exact command to run.
- **Pattern**: For this codebase (`lab-stock-nextjs`), additive migrations should be tested on a disposable Neon branch (`create_branch` → run twice to check idempotency → check constraint violations → `delete_branch`) before ever touching the production branch. This caught nothing new here (the migration was simple) but is cheap insurance and matches `05-lab-stock-nextjs.md`'s incremental/production-safe directive.
- **Pattern**: When print/export HTML is the deliverable, rendering it with headless Chrome (`--headless=new --screenshot`) and viewing the PNG is worth the extra step — it catches spacing/overflow issues that reading the template string cannot.
- **Pattern**: PO list endpoints in this codebase intentionally omit issuer/signer fields for payload size; any UI that prints/exports must fetch the single-PO detail endpoint first rather than assuming the list row has everything (found this the hard way when wiring up `vendor/orders/page.tsx`'s print button).
