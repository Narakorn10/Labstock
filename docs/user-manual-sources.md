# ที่มาของเนื้อหาคู่มือ (`/help`)

ไฟล์นี้ให้ผู้ตรวจทานเทียบว่าแต่ละขั้นตอนในคู่มือมาจากโค้ดตรงไหน คู่มือเขียนจากการอ่านโค้ด
**ไม่ได้มาจากการลองใช้หน้าจอจริง** จึงควรให้คนที่ใช้ระบบจริงอ่านตรวจก่อน merge

เนื้อหาอยู่ที่ `src/app/help/chapters.tsx` · หน้าแสดงผลอยู่ที่ `src/app/help/page.tsx`
ถ้าแก้หน้าใดที่คู่มืออ้างถึง ให้กลับมาอัปเดตบทนั้นด้วย (เทสต์ `chapters.test.tsx` ตรวจแค่ว่าหน้ายังมีอยู่)

## โครงคู่มือ (หน้าปก สารบัญ เลขหัวข้อ)

- หน้าปกมีเฉพาะฉบับ PDF (`PrintCover` ใน `page.tsx`) — วันที่บนปกคือ "วันที่กดพิมพ์" ไม่ใช่วันที่แก้เนื้อหา
- สารบัญและเลขหัวข้อ "ส่วน.บท" สร้างอัตโนมัติจาก `CHAPTERS` (`src/app/help/outline.ts`) — เพิ่มบทใหม่แล้วสารบัญอัปเดตเอง
- ฉบับ PDF ไม่มีเลขหน้าในสารบัญ (Chrome ยังไม่รองรับ CSS `target-counter`) แต่หัวข้อในสารบัญกดลิงก์ไปบทนั้นได้
- ส่วนที่ยังไม่มีบท แสดง "(กำลังจัดทำ)" ในสารบัญ

## ข้อสังเกตที่ผู้ตรวจควรรู้

1. **ข้อความในหน้าสมัครขัดกับโค้ด:** `register/page.tsx:363` เขียนว่า "ในระยะนี้ยังไม่มีการยืนยันอีเมลหรือการรีเซ็ตรหัสผ่าน"
   แต่มีหน้า `/reset-password` และ migration `upgrade_v20_password_reset.sql` แล้ว คู่มือเขียนตามหน้า `/reset-password`
   **ยังไม่ยืนยันว่าระบบส่งอีเมลรีเซ็ตได้จริงบน production** (ต้องมีการตั้งค่าส่งอีเมล) — ให้ทดลองกับบัญชีทดสอบ
2. กล่อง "สลับงาน" โชว์เฉพาะบัญชีที่ระบบสร้างข้อมูลงาน (`departmentContext`) ให้ ยังไม่ยืนยันเงื่อนไขที่แน่ชัดว่าใครเห็น
3. เมนูที่ผู้ใช้เห็นตั้งค่าได้จากหน้า Permissions ทุกบทจึงมีประโยค "ถ้าไม่เห็นเมนู ให้ติดต่อผู้ดูแลระบบ"
4. เมนู "Receive from Vendor" และ "Vendor Shipments" ถูกปิดด้วย `SHIPMENTS_ENABLED = false` (`src/lib/feature-flags.ts:3`)
   คู่มือ**ต้องไม่**พูดถึงการส่งของ (shipments) จนกว่า flag จะเปิด
5. หน้า `/help` ต้องล็อกอินก่อนอ่าน (ไม่ได้เพิ่มใน `isPublicPath` ตามที่ผู้ใช้ตัดสิน) จึงให้แจกไฟล์ PDF สำหรับคนที่ยังเข้าสู่ระบบไม่ได้
